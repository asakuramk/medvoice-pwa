# 音声で文書作成 — iPhone 単体版

Mac も証明書のインストールも不要で、**iPhone だけで**録音から文書の作成・受け渡しまで完結します。

はじめから使える文書は 6 種類。画面上部の「作成する文書」で切り替えます。**自分で文書を足すこともできます**（→「文書を追加する・削除する」）。

書き起こしは **iPhone の音声認識**（既定・無料）と、**録音して書き起こし API へ送る方法**（高精度・従量課金）から選べます（→「聞き取りの精度を上げる」）。

| テンプレート | 出力する項目 |
|---|---|
| 診療録（SOAP） | S / O / A / P |
| 看護記録（フォーカスチャーティング） | フォーカス / D（データ）/ A（アクション）/ R（レスポンス） |
| 問診（医療面接） | 主訴 / 現病歴 / 既往歴 / 内服薬 / アレルギー / 家族歴 / 生活歴 / 陽性・陰性所見 |
| 看護計画書 | 看護問題 / S・O / 長期目標 / 短期目標 / OP / TP / EP |
| 紹介状（診療情報提供書） | 紹介先 / 患者 / 傷病名 / 紹介目的 / 既往歴・家族歴 / 症状経過及び検査結果 / 現在の処方 / 備考 |
| 議事録 | 会議名 / 日時 / 出席者 / 議題 / 決定事項 / 検討内容 / 未決事項 / ToDo |

どのテンプレートでも共通して、**書き起こしに無い情報は加筆せず**、該当が無い項目は「記載なし」と出力します。
薬剤名の言い換え（フォシーガ→ダパグリフロジン等）と、数値の書き換えも禁止しています。
選んだテンプレートは端末に記憶され、次回もそのまま使えます。

**それぞれの指示は編集できます。**「作成する文書」の下の「✏️ 指示を編集」から、
Claude への指示をひとつづきの文章としてまとめて書き換えられます（→「テンプレートの指示を編集する」）。
`medical-voice/docs/仕様書_iPhone単体版.md` の実装です。

このフォルダの中身を HTTPS のどこかに置き、Safari で開いてホーム画面に追加するだけで使えます。

```
pwa/
├── index.html            アプリ本体（CSS / JS を内包）
├── manifest.webmanifest  ホーム画面追加用の情報
├── sw.js                 オフライン起動用の Service Worker
├── icon-180/192/512.png  アイコン
└── tools/make_icons.py   アイコンの生成スクリプト（通常は実行不要）
```

置いたサーバーはアプリの画面を返すだけです。API キーも患者情報も、そこを通りません。

## 1. 配信する（最初に 1 回だけ）

**HTTPS であることが必須です。** iOS Safari は HTTPS 以外のページでマイクを使えません。

### 方法 A — GitHub Pages（推奨・無料）

`asakuramk/lan-monitor` は private のため、GitHub Pages を無料で使うには**公開リポジトリを別に作ります**。
公開されるのはこのフォルダの中身（アプリの画面）だけで、既存のリポジトリは private のままです。

1. GitHub で新しい**公開**リポジトリを作る（例: `medvoice-pwa`）
2. このフォルダの中身（`index.html` / `manifest.webmanifest` / `sw.js` / `icon-*.png` / `.nojekyll`）をその直下に置く
3. リポジトリの **Settings → Pages** を開き、**Source** に **Deploy from a branch**、
   **Branch** に `main` と `/ (root)` を指定して **Save**
4. 1〜2 分後、`https://<ユーザー名>.github.io/medvoice-pwa/` で開けるようになる

手順 3 は最初の 1 回だけです。以降は push するだけで反映されます。
この手順は iPhone の Safari からでも行えます。

> Pages の有効化を GitHub Actions のワークフローで自動化することはできません。
> ワークフローの権限（`GITHUB_TOKEN`）では Pages サイトを新規作成できないためです。
> 静的ファイルだけの配信なので、Actions を使わない上記の方法が最も簡単です。

### 方法 B — Cloudflare Pages（リポジトリを公開したくない場合・無料）

private リポジトリのまま配信できます。

1. Cloudflare にアカウントを作り、Workers & Pages → Create → Pages → Connect to Git
2. `asakuramk/lan-monitor` を選び、ビルドコマンドは空、出力ディレクトリに `medical-voice/pwa` を指定
3. 発行された `https://<プロジェクト名>.pages.dev/` を使う

### 動作確認用（Mac のみ）

手元で確認したいときは、`http://127.0.0.1` はブラウザが安全なページとして扱うため、そのまま動きます。

```sh
cd medical-voice/pwa
python3 -m http.server 8000 --bind 127.0.0.1
# → http://127.0.0.1:8000
```

LAN の IP（`http://192.168.x.x`）ではマイクが使えません。iPhone から試すには上の A か B で配信してください。

## 2. iPhone に入れる

1. Safari で配信 URL を開く
2. 歯車アイコンから **Claude API キー**（`sk-ant-` で始まる文字列）を入力して「保存」
   - キーは https://console.anthropic.com/ で発行します
   - iPhone では、パスワード管理アプリからの貼り付けが楽です
3. 共有ボタン **⬆︎** → **「ホーム画面に追加」**
4. ホーム画面のアイコンから起動し、「録音開始」でマイクを **許可**

以降、Mac も同じ Wi-Fi も不要です。院外でも、モバイル通信でも同じ手順で使えます。

---

## 3. 使い方

0. 画面上部の **「作成する文書」** で作りたい文書を選ぶ
1. **「録音開始」** を押して内容を話す
   - iOS は数秒〜十数秒で音声認識を勝手に止めますが、自動で再開し続けます
   - 録音中は画面が消灯しないようにしています
   - **マイクの波形**と、**声を拾えているかの文字表示**が出ます。認識できていれば
     「声を認識しています（N 文字）」、しばらく何も入らなければ「声を拾えていないようです」と、
     端末の置き方を案内します
2. **「録音停止」** を押すと、**3 秒後に自動で作成が始まります**
   - 「キャンセル」で止められます
   - 書き起こしを直し始めた場合も自動で止まります
   - 自動で始めたくない場合は、設定のチェックを外してください
3. 書き起こしは**手で修正できます**。誤変換はここで直してから作成すると精度が上がります
4. できた文書は **「共有」** で他アプリへ渡すか、**「コピー」** で貼り付けます
5. **「破棄」** で書き起こし・メモ・作成結果・一時保存をまとめて消します（履歴は残ります）

## 履歴

録音を始めた時刻から 1 件を記録し、**書き起こし・メモ・作成結果・エラーまで**残します。
画面下の **「🕘 履歴」** を開くと、新しい順に一覧できます。

| できること | 内容 |
|---|---|
| 中身を見る | 項目をタップすると、書き起こし・メモ・作成結果の全文が開きます |
| コピー / 共有 | 作成結果をそのまま他アプリへ渡せます |
| **続きを録音** | そのセッションを開き、**続きから録音を足せます**（下記） |
| 削除 | 1 件だけ削除します |
| 書き出す | 全件をまとめてテキストで共有・コピーします |
| 全件削除 | すべて削除します |

### 題名

作成結果ができると、**内容から題名が自動で付きます**。書き起こしに人名（患者名・
出席者名など）があればその名前を入れ、無ければ内容の要点を 10 文字程度にまとめます。
書き起こしに無い名前を作ることはありません。題名が付くまで、または付けられなかった
場合は、書き起こしの冒頭が代わりに表示されます。

### 続きから録音する（セッションの継続）

診察が中断したとき、あとから聞き直したいことができたときのための機能です。

1. 履歴で目的の項目を開き、**「▶︎ 続きを録音」** を押す
2. 書き起こし・メモ・作成結果が入力欄に戻り、画面上部に **「作業中のセッション」** が出ます
3. そのまま **「録音開始」** を押すと、**前の書き起こしの続きとして書き足されます**
4. 録音を止めると、**追記後の全文でもう一度まとめ直します**（題名も付け直します）

履歴を開くと、**その記録を作ったときの文書形式が自動で選ばれます。** 議事録として
保存したものを開けば議事録に、紹介状として保存したものを開けば紹介状に戻ります。
そのまま録音すれば、同じ形式のまま書き足されます。

同じセッションの中で何回でも録音を足せます。一覧には「録音 3 回」のように回数と
合計時間が出ます。別の項目の「続きを録音」を押せば、**そちらのセッションに切り替わります。**
新しい記録を始めるときは、セッション欄の **「＋ 新規」** を押してください。

### 作り終えたあとの録音は、新しい記録になります

**文書を作り終えたあとにもう一度「録音開始」を押すと、自動的に新しい記録として始まります。**
「＋ 新規」を押す必要はありません。SOAP を続けて何件も取るときは、そのまま録音を始めてください。

作成が済むとセッション欄に「作成済みです。次に録音を始めると新しい記録になります」と予告が出ます。
実際に切り替わるのは **録音を始めたとき**で、前の内容は履歴に残ります
（履歴を「保存しない」設定にしている場合のみ、消してよいか確認します）。

**まだ作成していない**うちは、これまでどおり同じ記録に書き足されます。
一度止めて言い足すときは、そのまま録音を続けてください。

**作成済みの記録に足したい**ときは、履歴からその 1 件を「▶︎ 続きを録音」で開いてください。
開いたあとの録音は、その記録の続きとして書き足されます。

### 文書を変えて録音すると新しい記録になります

**「作成する文書」を変えてから録音を始めると、自動的に新しいセッションになります。**
別の文書を作るということなので、前の内容には書き足しません。

変更した時点ではまだ何も消えません。セッション欄に「次に録音を始めると新しい
セッションになります」と予告が出るだけで、実際に切り替わるのは **録音を始めたとき**です。
前の内容は履歴に残ります（履歴を「保存しない」設定にしている場合のみ、消してよいか確認します）。

書き起こしはそのままに **形式だけ変えて作り直したい**ときは、文書を変えてから
録音ではなく **「生成」** を押してください。同じセッションのまま作り直します。

**保存期間を過ぎたものは自動で削除されます。** 期間は設定で選べます
（7 日 / 30 日 / 90 日 / 1 年 / 保存しない）。既定は **30 日**です。
期間内でも最大 300 件までで、超えた分は古いものから消えます。

> **患者情報が端末に残ります。** 端末のパスコード / Face ID を必ず有効にし、
> 共用端末では使用後に「全件削除」を押してください。履歴を残したくない場合は、
> 設定で「保存しない」を選ぶと、記録済みの履歴もその場で削除されます。
>
> なお iOS の仕様上、7 日以上アプリを開かないと保存期間内でも履歴が消えることがあります。
> 残しておく必要がある記録は、その都度電子カルテへ渡してください。

書き起こしが同じでも、テンプレートを変えて何度でも作り直せます。

### テンプレートの指示を編集する

「作成する文書」の下の **「✏️ 指示を編集」** を押すと、選んでいる文書の指示を書き換えられます。

**役割・項目の説明・制約・出力形式は 1 つの入力欄にまとまっています。**
そこに入っている文章がそのまま Claude に送られるので、院内の様式に合わせて自由に書き直せます。

- 編集は**この端末にだけ**保存され、文書ごとに別々に持てます
- **空欄にすると既定の指示に戻ります**
- 「この設定で送られる指示を確認する」で、実際に送る文面を確認できます
- 元に戻したいときは「既定に戻す」。編集していると「✏️ 指示を編集済み」と表示されます

**共通の制約（書き起こしに無い情報を加筆しない、該当が無い項目は「記載なし」、薬剤名を言い換えない、
数値をそのまま転記する など）は、消しても送信時に必ず付け直します。**
消えている制約は編集画面に警告として表示されます。全文は「すべての文書に必ず付く制約」で確認できます。

指示を変えても、作っている文書の種類は同じままなので、**録音中のセッションはそのまま続きます。**

### 文書を追加する・削除する

6 種類のほかに、**自分で文書を追加**できます。要約・報告書・申し送りなど、
文章を整えるだけの用途にも使えます。

**追加する**

1. 「作成する文書」の下の **「＋ 文書を追加」** を押す
2. **名前**（一覧に出る名前。例: 退院サマリー）を入れる
3. **呼び方**（「◯◯を生成」に使う短い言い方。例: サマリー）は任意。空欄なら名前をそのまま使います
4. **指示**は、共通の制約が入った下書きが最初から入っています。役割・項目の説明・出力形式を書き換えます
5. 「追加する」を押すと一覧に増え、そのまま選ばれます

指示の書き方は既定の文書と同じで、**入力欄の文章がそのまま Claude に送られます。**
「この設定で送られる指示を確認する」で最終的な文面を確認できます。
**共通の制約は、自分で追加した文書にも必ず付きます。**

**削除する・一覧から外す**

| 対象 | 操作 |
|---|---|
| 自分で追加した文書 | その文書を選んで「✏️ 指示を編集」→ **「削除」** |
| はじめからある 6 種類 | 消せません。使わないものは **「一覧から外す」** で隠せます |

- 外した文書は編集画面の **「一覧から外した文書」** から、いつでも一覧に戻せます
- すべての文書を外すことはできません（最後の 1 つは残ります）
- 削除しても、**その文書で作った履歴は残ります**（履歴から開くと既定の文書として開きます）
- 追加した文書は最大 20 件までです

### 聞き取りの精度を上げる

音声認識そのものは **iPhone（Apple）の機能**で、アプリ側から認識エンジンの精度を
変えることはできません。そのうえで、次の工夫で実用上の精度は上げられます。

**① 外付けマイク（Bluetooth・有線）を使う**

いちばん確実なのは、**話し手の近くにマイクを置く**ことです。
Bluetooth のピンマイクや小型の会議マイクを繋いだら、設定の **「使うマイク」** で選んでください。

1. 設定（⚙️）を開く
2. **「マイクを調べ直す」** を押す（マイクの名前を出すために一度だけ許可が要ります）
3. 一覧から使いたいマイクを選ぶ

- 選んだマイクは次回も使われます。外していたときは**端末のマイクで録音を続けます**（その旨が出ます）
- ⚠️ **「iPhone の音声認識」ではマイクを選べません**（iOS の仕様で、端末が選んだ入力が使われます）。
  外付けマイクを確実に使うには、下の②「録音して書き起こす方法」と組み合わせてください
- ⚠️ Bluetooth のマイクは**通話用の音質**（狭い帯域）になることがあり、内蔵マイクより悪くなる場合もあります。
  有線のピンマイクのほうが安定することが多いので、両方お試しください

**② 録音して書き起こす方法に切り替える（外来ではこちらを推奨）**

iPhone の音声認識は**近くで 1 人が口述する**用途に作られています。医師と患者が
離れて交互に話す外来では、当院の実機で **1 分あたり 20〜30 文字**しか取れませんでした。
この場合は、設定の **「書き起こしの方法」** を
**「録音して書き起こし API へ送る」** に変えてください。

- 録音を止めると、音声を書き起こしサービスへ送って文字にします（長い録音は 4 分ごとに送ります）
- 距離・複数の話し手・言い直しに強く、実用的な精度になります
- **書き起こし用の API キーがもう 1 つ必要です**（Claude のキーとは別。設定の同じ「保存」で保存されます）
- 既定は OpenAI の書き起こしですが、**送信先とモデル名は設定で変えられます**
- 費用は使った分だけかかります（各サービスの料金をご確認ください）

⚠️ **この方法では、録音した音声が書き起こしサービスへ送られます。**
文字にした時点で音声は破棄し、端末にも保存しませんが、
音声が端末の外へ出る点は既定の方法と大きく違います。院内の規程をご確認ください。
送信に失敗した音声だけはその場に残り、「再送信」で送り直せます。

**③ 波形のオン／オフを、同じ場面で見比べる**（iPhone の音声認識を使う場合）

波形はマイクを**もう 1 つ開いて**描くため、聞き取りに影響することがあります。
ただし**良くなるか悪くなるかは端末や場所によって変わります**（当院の実機では、
オンで悪い場面と、オフにしたらさらに悪くなった場面の両方がありました）。

そこで、決め打ちにせず**試して選べる**ようにしています。

1. いつもの場所で 1 分ほど録音し、停止する
2. 設定の **「マイクと認識の状態」** を開き、**「確定した文」と「文字数」**を控える
3. 設定の**波形のチェックを切り替えて**、同じように 1 分録音する
4. 文字数が多かったほうの設定にしておく

**④ 用語集に登録する**

設定の **「よく使う語（用語集）」** に、院内でよく使う薬剤名・術式・人名・部署名を
1 行に 1 語ずつ入れておきます。

```
フォシーガ
アムロジピン
胃瘻造設
ほしいが→フォシーガ
```

- そのまま書いた語は、**認識の候補にその語があればそちらを採用**し、
  文書の作成時にも「この施設で使う表記」として Claude に渡します
- **「まちがい→ただしい」**と書くと、書き起こしの時点で置き換えます。
  いつも同じように誤認識される語は、この形で登録するのが確実です

登録した語に**寄せて直すだけ**で、書かれていない語を足すことはしません。
薬剤名の意味的な言い換え（先発名 ↔ 一般名）は、用語集を使う場合も行いません。

**⑤ 話し方・環境**

- **マイクは iPhone の下端**です。手やケースで塞がないでください
- **下端を話し手のほうへ向け、30〜50cm 以内**に置いてください。机に伏せて置くと拾いません
- 患者さんと医師の中間に置くと両方を拾えますが、**離れるほど急に精度が落ちます**
- テレビ・空調・キーボードの音は認識精度を下げます
- ひと息で長く話すより、**文単位で区切る**ほうが確実です
- 数値は「三十七度五分」より「37.5 度」のように、はっきり区切って読むと安定します

**⑥ 書き起こしを直してから作成する**

書き起こし欄はいつでも手で直せます。**誤認識のまま作成するより、明らかな誤りを
直してから「生成」を押すほうが、できあがりは確実に良くなります。**
固有名詞と数値だけ確認する、という使い方をおすすめします。

### 音声が使えないとき

書き起こし欄に直接入力すれば診療録は作成できます。
iOS で音声認識に対応しているのは **Safari だけ**です。Chrome や LINE のアプリ内ブラウザでは録音ボタンが使えません。

## 4. 端末に保存されるもの

| 内容 | 消し方 |
|---|---|
| API キー | 設定の「消去」 |
| 入力内容の一時保存（最新の 1 件） | 「破棄」、または設定で一時保存をオフ |
| 履歴（書き起こし・メモ・作成結果） | 保存期間で自動削除。「削除」「全件削除」、または設定で「保存しない」 |
| 表示設定（テンプレート・保存期間・用語集・使うマイクなど） | Safari の履歴・データ消去 |
| 編集したテンプレートの指示 | 編集画面の「既定に戻す」、または Safari の履歴・データ消去 |
| 自分で追加した文書 | 編集画面の「削除」、または Safari の履歴・データ消去 |
| 書き起こし用の API キー | 設定でキー欄を空にして「保存」、または Safari の履歴・データ消去 |
| 録音した音声 | **端末には残りません**（文字にした時点で破棄します）。送れなかった分だけ、アプリを閉じるまでその場に残ります |

いずれも端末内にのみ保存され、配信元のサーバーへは送られません。

7 日以上アプリを開かないと、iOS が保存内容（API キーを含む）を消すことがあります。
その場合はアプリがその旨を表示するので、キーを入れ直してください。

## 5. 困ったときは

| 症状 | 対処 |
|---|---|
| 書き起こしに失敗しましたと出る | キーと送信先を確認してください。録音は残っているので「再送信」で送り直せます。401 ならキー、429 なら利用上限です |
| 書き起こしが返ってこない | 通信環境を確認してください。オフラインでは書き起こし API を使えません。設定で「iPhone の音声認識」に戻せば、通信なしでも文字にはなります |
| ほとんど聞き取れない | まず端末の下端を話し手へ向け、30〜50cm 以内に置いてください。それでも変わらない場合は、**設定の波形のチェックを切り替えて**同じ場面で試し、「マイクと認識の状態」の文字数を見比べてください |
| Bluetooth マイクが一覧に出ない | 先に iPhone 側で接続してから、設定の「マイクを調べ直す」を押してください。名前を出すには一度マイクの許可が必要です |
| 外付けマイクにしたら悪くなった | Bluetooth は通話用の音質になることがあります。「端末のマイク（自動）」に戻すか、有線のマイクをお試しください |
| 声を拾えているか分からない | 録音中の表示を見てください。「声を認識しています」なら届いています。「声を拾えていないようです」なら置き方を変えてください |
| 原因が分からない | 設定の**「マイクと認識の状態」**を開き、「この内容をコピー」で内容を控えてください。認識の回数やエラーの内訳が入っています |
| 聞き取りが安定しない | 用語集に登録し、マイクを塞がず、文単位で区切って話してください（→「聞き取りの精度を上げる」） |
| 波形が平らなまま動かない | まず自動で立て直します（「マイクを再開しています」「取り直しています」と出ます）。それでも直らない場合は、マイクを手で塞いでいないか、イヤホンやマイク付きケーブルが挿さっていないかを確認してください。iPhone 本体のマイクは下端にあります |
| 「波形を表示できません」と出る | マイクが音声認識や他のアプリに使われています。**録音と書き起こしは続いています。**気になる場合は録音を止めて開き直してください |
| 波形が出ない（録音自体はできる） | 設定で波形の表示がオフになっていないか確認してください。オンでも出ない場合はマイクの取得に失敗しています。録音と書き起こしには影響しません |
| 更新したら波形が消えた | 一時的に波形を既定でオフにした版がありました。次の版で元に戻しています。設定でいつでも切り替えられます |
| マイクが反応しない | 「設定」→「Safari」→「マイク」を **許可**／「設定」→「一般」→「キーボード」→「音声入力」を **オン** |
| ホーム画面のアイコンから起動するとマイクが使えない | Safari で同じ URL を開いて使ってください（iOS の既知の問題） |
| 「HTTPS で開いていない」と出る | `https://` の URL で開き直してください |
| 録音ボタンが押せない | Safari で開いてください。または書き起こし欄に直接入力してください |
| 圏外で「作成できません」と出る | 録音と編集はオフラインでもできます。入力は保存されているので、通信が戻ってから作成してください |
| API キーが消えた | 7 日以上未使用だと iOS が消すことがあります。入れ直してください |
| 追加した文書が保存できない | 保存領域がいっぱいか、プライベートブラウズの可能性があります。履歴を減らすか、通常のタブで開いてください |
| 一覧から文書が消えた | 「✏️ 指示を編集」→「一覧から外した文書」から戻せます |

## 6. 取り扱いの注意

- **API キー** — ブラウザから Claude API を直接呼ぶ構成のため、キーは端末内に保存されます。**個人の端末での利用**を前提としてください。このアプリ専用のキーを発行し、[コンソール](https://console.anthropic.com/)で使用上限を設定し、iPhone 本体のパスコード / Face ID を有効にしておくことを勧めます
- **患者情報** — 書き起こしと診察メモは、診療録の作成時に Anthropic の API へ送信されます。取り扱いは所属機関の規程に従ってください
- **音声** — 録音した音声そのものは保存も送信もされません。音声認識は端末側で行われ、送信されるのは文字列だけです
- **公開リポジトリを使う場合** — アプリのソースは誰でも読めます。院内の運用手順や固有名詞をソースに書かないでください

## 7. 更新のしかた

`index.html` などを変更したら、**`sw.js` の `VERSION` を上げて**から配信元に反映します。

```js
var VERSION = 'v2';   // v1 から上げる
```

利用者の端末では次回起動時に「新しい版があります」と表示され、「再読み込み」で切り替わります。
入力中の内容は保持されます。

アイコンを作り直す場合のみ `python3 tools/make_icons.py` を実行します。
